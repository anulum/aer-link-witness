# Repository architecture

## Current executable tooling

Metadata, source-provenance, workflow, dependency-alignment, documentation, inventory and preflight controls inspect their declared local scopes. Native-tool bootstrap checks selected executable and licence files. Received metadata cannot choose policy or grant link acceptance. Foundation qualification is in progress.

## Intended link-evidence boundaries

| Component | Responsibility | Required evidence |
| --- | --- | --- |
| Traffic | All prior constant, burst, hot-spot, head-of-line, starvation-seeking and deadlock-seeking schedules | Complete load, repetition and flow population, payload progression, routes and finite limits |
| Instrument | Source-owned generator and monitor | Independent simulation, actual adapter sampling and raw-byte interpretation |
| Capture | Consume admitted timebase and full observations | Original raw order, identities, epochs, coverage, overflow, pending work and durable checkpoints |
| Analysis | Independent exact sequence and pending-work interpretation | Expected delivery membership, payload, time windows, censored delay and qualifying progress |
| Report | Assemble full native record through installed shared provider | Same source, complete cells, raw/reference closure and truthful verdict |
| Consumers | Independently replay and render existing result | Installed separate consumers and actual Studio journey |

The planned report has eleven required members: schema_id, claims, source_ref, environment_ref, dut, lane, patterns, timebase, capture_ref, rows and verdict. This is a planned declaration, not registered or qualified domain support.

Five prospective library operations are generate_pattern, capture, analyse, report and verify. Proposed command spellings are generate-pattern, capture, analyse, report and verify. A future run convenience composes generation and capture with both real operation receipts. None is installed or advertised as available.

The four initial source-owned DUTs have different interfaces. Encoder inputs are spike bits with coalesced pending work and no ready input. Service clearing takes precedence over a simultaneous new spike on the served bit; emitted timestamp is service time. Preserve original spike opportunities and actual services separately.

Router input packets can expand into ordered configured fanout deliveries. Bind complete route, target, weight and priority tables. Source-ready, output backpressure, unknown HDL values and representable source/target/fanout widths need exact adapter interpretation. Queue priority zero is highest; retained scan order determines ties. Simultaneous enqueue/dequeue, occupancy, dropped-event and sticky deadline state remain visible.

Axonal delay exposes spike/tap signals and circular state, with zero-offset combinational passthrough. Optional step enable holds stored spikes and head; passthrough can still reflect current input. Bind exact source version, enable, reset and pre/post-edge sampling. Do not fabricate packet IDs or a ready/valid interface.

A prior complete plan binds source/compiler/elaboration, adapters, reset and warmup, payload/flow/route/priority, clock epochs, every schedule/load/repeat/flow cell and capture/drain/watchdog/stop policy. Rational seconds map to ticks under an explicit conversion and refusal rule. Nominal model ticks are not measured time.

Keep offered spike opportunities, accepted packets, expected fanout deliveries and unique legitimate receipts distinct. A valid receipt has the expected identity, unchanged payload and supported time in the prior half-open capture/drain scope. Preserve duplicate, unexpected, payload-mismatch, before-offer, outside-window, missing and unknown records separately. Raw order determines simultaneous receipt order.

Reordering counts legitimate unique per-flow receipts below the prior running maximum, not pairwise inversions. Throughput uses the prior declared observation duration, including drain when selected. Zero-loss requires nonempty complete expected traffic, clean coverage and exact receipt accounting; duplicates cannot create negative loss. Pending or censored required work makes the full service-delay maximum unavailable. A received-only maximum never becomes a universal starvation bound.

Watchdog failure requires continuously pending work, complete observation and no qualifying progress over the entire prior half-open window. Idle is not deadlock. Gaps or unknown pending state remain unavailable. Source sticky deadlines are distinct from watchdog policy findings; later attempts retain earlier failures.

Actual capture needs admitted raw byte encoding and decoder, not an authored analytic trace. Acquisition resume starts a new attempt and retains predecessor and last durable ordinal. Existing raw bytes precede inventories, analysis, native report, shared manifest, signatures and later receipts. No signature or matching hash proves instrument independence, measured time or link correctness.

Every failed, missing, unavailable and interrupted cell remains in the whole population. Instrument simulation verifies instrumentation; measured fabric additionally needs actual board, source, clock, coverage and uncertainty acceptance. Finite load sweeps cannot establish universal capacity or probabilistic zero-loss rates. Read [validation tooling](validation-tooling.md) for executable repository interfaces.
